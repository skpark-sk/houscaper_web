도구 선정 배경

왜 VS Code + Roo Code 인가

도구이 강의에서의 위치이유
Cursor 강사 메인 · 학생 서브 무료 한도가 금방 소진된다. 외부 키를 넣어도 탭 자동완성 같은 핵심 기능은 자체 크레딧에 묶여 있다.
VS Code + Roo Code / Cline 학생 메인 권장 애초에 BYOK(본인 키 사용) 구조라 한도 제약이 없다. MCP 연결도 GUI로 설정할 수 있다.
Claude Code 중급 이후 터미널 기반이라 MCP 설정이 처음엔 불편하다.
Orca (ADE) 이번 강의 제외 여러 에이전트를 깃 워크트리에 병렬로 굴리는 도구. 입문자에겐 과하다.

도구는 계속 바뀝니다. 본인 키를 자유롭게 꽂을 수 있는 구조인지가 선택 기준입니다.

핵심 전략
무료 키를 여러 개 발급받아 두고,
한도가 떨어지면 갈아끼운다.

키를 바꿔 끼우는 이 과정 자체가 좋은 실습 소재입니다. 오늘 두 번 해봅니다.

  • 키는 사람마다 따로 발급합니다. 강사 키를 공유하지 않습니다.
  • 한도가 끊기는 건 사고가 아니라 예정된 일입니다.
  • 도구가 아니라 연결 방식을 배웁니다. 제공처가 바뀌어도 절차는 같습니다.

오늘 키를 두 곳에서 발급받는 이유입니다. 하나가 막혀도 실습이 멈추지 않습니다.

문법을 외우는 대신, 무엇을 만들지 정확히 말하는 능력이 실력이 됩니다.

  • 모델은 계속 바뀝니다. 남는 것은 작업 흐름입니다.

1교시 · API 키

키는 비밀번호다

API 키는 내 계정으로 요금을 발생시킬 수 있는 출입증입니다. 코드 안에 직접 적지 않고 .env 파일에 넣은 뒤, 그 파일을 .gitignore로 막습니다.

# .env
NVIDIA_API_KEY=nvapi-xxxxxxxxxxxx
GEMINI_API_KEY=AIzaSy-xxxxxxxxxxxx
# .gitignore
.env
.env.*
node_modules/
  • .gitignore를 먼저 만들고 키를 넣습니다. 순서가 중요합니다.
  • 한 번 올라간 키는 지워도 기록에 남습니다. 즉시 폐기하고 재발급합니다.

키를 직접 코드에 적어 본 적이 있다면, 지금 그 파일부터 확인해 주세요.

실습 전 · 반드시
발급받은 키를 화면 공유나
깃허브에 그대로 올리지 않습니다.
수업 중 자주 나오는 사고 발급 화면을 그대로 띄운 채 화면 공유 · 스크린샷에 키가 찍힘 · 테스트 코드에 키를 하드코딩한 채 커밋. 셋 다 한 번의 붙여넣기에서 시작합니다.

키가 노출된 것 같다면 부끄러워하지 말고 바로 말해 주세요. 폐기 후 재발급이 유일한 해결책이고, 1분이면 끝납니다.

2교시 · OpenAI 호환

바꾸는 건 두 줄뿐이다

from openai import OpenAI

client = OpenAI(
    base_url="https://integrate.api.nvidia.com/v1",
    api_key=os.environ["NVIDIA_API_KEY"],
)

resp = client.chat.completions.create(
    model="deepseek-ai/deepseek-r1",
    messages=[{"role": "user", "content": "안녕"}],
)
  • 기존 OpenAI SDK 코드에서 base URL과 모델명만 바꾸면 그대로 돕니다.
  • 확장 프로그램 설정도 같은 원리입니다. Provider를 OpenAI Compatible로 고르는 이유입니다.
  • 무료 크레딧은 대략 1,000회 호출 수준. 코딩 실습에서는 빠르게 소진됩니다.

그래서 키를 갈아끼우는 일이 예외가 아니라 기본 동작이 됩니다.

2교시 · 실습

연결하고 바로 시켜본다

  1. STEP 1VS Code 확장 마켓플레이스에서 Roo Code 또는 Cline 검색 후 설치
  2. STEP 2설정에서 Provider를 OpenAI Compatible로 선택
  3. STEP 3Base URL · API Key · 모델명 입력
  4. STEP 4첫 프롬프트로 동작 확인 — "이 폴더에 hello world 웹페이지 만들어줘"
  5. STEP 5키 교체 실습 — Gemini 키로 갈아끼우고 같은 작업을 다시 실행

같은 프롬프트를 다른 모델로 두 번 돌려 보고, 결과가 어떻게 달라지는지 비교합니다.

3교시 · MCP

MCP는 AI의 손이다

Model Context Protocol — AI가 외부 도구와 데이터에 접근하는 표준 통로입니다. 대화만 하던 모델이 파일을 읽고 도구를 쓰게 됩니다.

AI 모델무엇을 할지 판단
→
MCP 서버표준 규격의 통로
→
파일 · API · DB실제 도구와 데이터
  • VS Code 확장(Roo Code / Cline)에서는 설정 파일에 서버를 등록하는 방식입니다. Cursor와 개념적으로 동일합니다.
  • 오늘 실습: 파일시스템 MCP 같은 기본 서버 1개를 연결해 봅니다.
